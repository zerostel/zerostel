**どんな AI エージェントも、ゼロ地点まで巻き戻す。**

AI エージェントのためのゼロトラスト：壊すものと想定し、すべてのステップを記録し、触ったファイルを巻き戻せるようにする。
コーディングエージェントのためのフライトレコーダー兼タイムマシン。自分で決めるガードレールと、改ざんを検証できるログ付き。

```bash
npx zerostel install
```

まず試してみたいなら：`npx zerostel demo` は使い捨てのサンプルプロジェクトを作り、エージェントがフォルダを削除してテストを壊すターンを再現し、それを undo で戻せます。エージェントは不要で、あなたのプロジェクトには触れません。

あとはいつも通りエージェントを使うだけです。何かを壊されたら：

```bash
zerostel log          # 何が起きたかをステップごとに確認
zerostel undo         # ファイルをエージェントの直前のターンより前に戻す
zerostel rewind 0     # セッション開始時点（ゼロ地点）まで一気に戻す
zerostel ui           # 同じことをローカルの Web ページで
```

## なぜ必要か

エージェントは一度に何十ものファイルを編集し、`rm`、`git checkout .`、マイグレーション、ビルドスクリプトも実行します。問題が起きたとき知りたいのは、「何をしたのか」と「どう戻すのか」です。

チェックポイントを持つエージェントもありますが、仕組みはまちまちです。Claude Code の rewind は Bash 経由の変更を含みません。Copilot CLI はシェルコマンドも追跡します。Cursor や Codex にもそれぞれ独自の仕組みがあります。複数のエージェントを使うと、「何が変わって、戻せるのか」の答えがエージェントごとに違ってしまいます。

Zerostel は対応するすべてのエージェントを同じ方法で記録します。ファイルを変更しうるツール呼び出しの前後でプロジェクトのスナップショットを取り、プロンプト・コマンド・ファイル・時間・トークンのタイムラインを残し、他の人に渡せるレポートを出力します。あなたの `.git` には一切触れません。

| | エージェント組み込みのチェックポイント | コミット／`git stash` | **Zerostel** |
|---|---|---|---|
| シェルコマンドによる変更 | エージェント次第 | コミットした分だけ | ✅ プロジェクト内と、指定したファイル |
| 特定のステップに戻る | 多くはプロンプト単位 | コミット単位 | ✅ ツール呼び出し単位 |
| コマンド・ファイル・トークン・時間のタイムライン | 一部 | ❌ | ✅ |
| 後からログの改ざんを検証できる | ❌ | ✅（コミットハッシュ） | ✅ |
| 独自ルールで実行前にブロック・確認 | エージェントごと | ❌ | ✅ すべてのエージェントで同じルール |
| エージェント間で同じ動作 | ❌ それぞれ別 | ✅ | ✅ |
| あなたの `.git` に書き込む | 一部あり | ✅ | ❌ 決してしない |
| 共有できるセッションレポート | ❌ | ❌ | ✅ |

詳細と出典：[docs/comparison.md](docs/comparison.md)

## ゼロトラストを実際にどう実現しているか

名前に込めた考え方：普段おとなしいからといってエージェントを信頼しない。間違えるものと想定し、すべての行動を見て、戻る道を確保しておく。現在 Zerostel が実現していること：

| 原則 | ここでの意味 |
|---|---|
| **侵害を前提にする** | ファイルを変更しうるツール呼び出しの前後に必ずスナップショット。どのターンも取り消せ、どのステップにも、ゼロ地点にも戻れます。 |
| **すべてを見る** | プロンプト、ツール呼び出し、コマンド、ファイル変更、所要時間、トークンを、セッションごとに 1 本のタイムラインで。 |
| **記録を検証する** | ログの各行は、鍵付きハッシュで前の行とつながっています。`zerostel verify` は編集・削除・並べ替えされた行を指摘します。 |
| **記録はエージェントのものではない** | 入門ルールは `~/.zerostel` へのアクセスを禁止し、エージェントが Zerostel を削除したりフック設定を変えたりするときは先に確認します。ルールは言い換えで回避されうるが、ログは残る：セッション中にフックが外されると、次のフック呼び出しがそれを記録します。 |
| **最小権限、ルールは自分で** | `~/.zerostel/policy.json` のガードレールが、ツールの実行前にブロックするか、まずあなたに確認させます。 |
| **被害範囲を限定する** | 巻き戻しはプロジェクト、指定したファイル（`~/.zshrc` など）、Windows ではユーザー環境変数が対象。巻き戻し自体も取り消せます。巻き戻せないことは事前に確認するか（入門ルールを参照）、元に戻すためのコマンドを示します。 |
| **読み込むものを信頼しない** | Zerostel はどのプロジェクトも悪意があるものとして扱います。中のプログラムを実行せず、リンクをたどって外に出ず、端末制御コードを除去します。 |

できないこと：サンドボックスではありません。ネットワークリクエスト、デプロイ、データベースへの書き込みは戻せず、あなたの権限で動くエージェントはあなたにできることができます。[制限](#制限)をご覧ください。

## インストール

```bash
npx zerostel install          # その場で実行、グローバルには入れない
npm install -g zerostel       # zerostel コマンドを常に使えるようにする
```

`npx` は信頼できるフォルダ（ホームフォルダなど）で実行してください。プロジェクトのフォルダ内では、npx はそのプロジェクトが用意した同名のパッケージを優先します。git が必要です。npm で入れる場合は Node 20 以上も必要です。Node がない場合は、各リリースに Node を内蔵した単一の実行ファイル（Windows・macOS・Linux、x64 と arm64）があります。[Releases](https://github.com/zerostel/zerostel/releases) からダウンロードして `zerostel install` を実行すると、自身を `~/.zerostel/bin` にコピーします。`gh attestation verify <ファイル> --repo zerostel/zerostel` で、このリポジトリのリリースワークフローでビルドされたものか確認できます。Homebrew と Scoop のパッケージは準備中です。テンプレートは [packaging/](packaging) にあります。

`zerostel install` は自身を `~/.zerostel/bin` にコピーするので、npx のキャッシュが消えてもフックは動き続けます。そのうえで見つかったエージェントすべてにフックを追加します。変更内容を表示し、編集する設定ファイルはすべてバックアップします。

### プラグイン、拡張機能、スキル

各エージェントのプラグインの仕組みからも Zerostel をインストールできます。どれにも同じ `zerostel` スキルが付いていて、タイムラインの読み方、巻き戻しはプレビューしてから確認を取ること、記録には手を出さないことをエージェントに教えます。

| エージェント | エージェント内で実行 | 追加されるもの |
|---|---|---|
| Claude Code | `/plugin marketplace add zerostel/zerostel` のあと `/plugin install zerostel@zerostel` | 記録、ガードレール、スキル |
| Codex | `codex plugin marketplace add zerostel/zerostel` のあと、プラグイン一覧から Zerostel をインストール | スキル（記録は `zerostel install`） |
| Antigravity | `agy plugin install https://github.com/zerostel/zerostel` | スキル（記録は `zerostel install`） |
| Gemini CLI | `gemini extensions install https://github.com/zerostel/zerostel` | スキル（記録は `zerostel install`） |
| スキルを読むその他のエージェント | `npx skills add zerostel/zerostel` | スキル |
| MCP クライアント | [MCP Registry](https://registry.modelcontextprotocol.io) の `io.github.zerostel/zerostel` | MCP サーバー（下記参照） |

Claude Code では、プラグインと `zerostel install` はどちらか一方で十分です。両方が有効でも、イベントは一度だけ記録されます。MCP サーバーを自動で起動するプラグインはありません。追加するのはあなたで、実行するプログラムもあなたが選びます（下記参照）。

## 対応エージェントとシステム

| エージェント | 方式 | 状態 |
|---|---|---|
| Claude Code | フック | ✅ 実セッションで確認済み |
| Codex | フック（初回のみ `/hooks` で承認） | ✅ 実セッションで確認済み |
| Cursor | フック | ✅ CLI を実セッションで確認済み。CLI はプロンプトのイベントを送らないため、CLI では undo が 1 変更ずつ戻ります。Windows では PowerShell から起動してください（Git Bash から起動するとフックが動きません） |
| Gemini CLI | フック（信頼済みフォルダのみ） | ✅ エンドツーエンドで確認済み¹。Code Assist Standard／Enterprise と有料 API キー向け（個人アカウントは 2026 年 6 月に Antigravity へ移行） |
| Antigravity（CLI、デスクトップ、IDE） | フック | ✅ エンドツーエンドで確認済み¹。プロンプト本文は渡されないため、ターンは「New turn」と表示 |
| Copilot CLI | フック（`~/.copilot/hooks`） | ✅ 実セッションで確認済み |
| opencode | プラグイン | ✅ 実セッションで確認済み |
| DeepSeek Harness | プラグイン | 🧪 実験的（dsh 自体が開発者プレビュー）。エンドツーエンドで確認済み¹ |
| その他（Aider、スクリプトなど） | `zerostel run -- <コマンド>` でファイルを監視 | ✅ 粗め：ツール呼び出し・トークン・ガードレールなし |

¹ Windows で本物のエージェントを動かし、モデルだけを台本どおりに応答する偽モデルに置き換えて確認：プロンプト、ファイル書き込み、コマンド実行、ルールで止められた呼び出し、ターンの終了、undo。

実験的なエージェントは名前を指定したときだけインストールされます（例：`zerostel install --agent deepseek`）。実際の利用状況の報告を歓迎します。

エージェントの裏にあるモデルは問いません。Claude、GPT、Gemini、DeepSeek、ローカルモデルのいずれも同じように記録します。

Windows、macOS、Linux（WSL を含む）に対応。CI はすべてのコミットを 3 つの OS と Node 20／22／24 でテストしています。

## コマンド

**記録**

| コマンド | |
|---|---|
| `zerostel install` | このマシンで見つかったエージェントにフックを追加。`--agent gemini,copilot` で指定、`--agent all` で実験的でないものすべて。 |
| `zerostel run -- <コマンド>` | フックなしで任意のエージェントやスクリプトを記録。ファイルの変更が落ち着くたびにスナップショットを取ります。 |

**見る**

| コマンド | |
|---|---|
| `zerostel log` | このプロジェクトの最新セッションのタイムライン。`-n 20` で最後の 20 ステップ、`--changes` でファイルを変更したステップのみ。 |
| `zerostel ui` | セッション・タイムライン・差分をローカルの Web ページで表示。巻き戻しと取り消しのボタン付き。 |
| `zerostel sessions` | このプロジェクトで記録されたすべてのセッション。 |
| `zerostel show <n>`／`zerostel diff <n>` | ステップ *n* のコマンド・出力・ファイル、または正確な差分。 |
| `zerostel find <パス>` | すべてのセッションで、そのファイルに触れたステップ。 |

**戻す**

| コマンド | |
|---|---|
| `zerostel undo` | ファイルを変更したエージェントの直前のターンより前に戻します。直後にもう一度実行すると undo を取り消せます。 |
| `zerostel rewind <n>` | ステップ *n* の直前に戻します（`--after` で直後、`0` でゼロ地点）。*n* を省くとステップを一覧表示して選べます。`--only <パス>` で一部だけ、`--dry-run` でプレビュー。 |
| `zerostel snapshot -m "メモ"` | 手動でチェックポイントを保存。 |

**共有と検証**

| コマンド | |
|---|---|
| `zerostel report --open` | セッションを単体の HTML ページとして出力。 |
| `zerostel report --share` | 他の人向けの版。プロンプト・コマンド・出力・差分をファイルに含めません。 |
| `zerostel verify` | 記録後にセッションのログが編集されていないか確認（`--all` ですべて）。 |

**ガードレール**

| コマンド | |
|---|---|
| `zerostel policy init` | 入門用のルールを作成：認証情報には触れさせず、強制プッシュや `.env` の編集の前に確認。 |
| `zerostel policy` | ルールを表示。 |
| `zerostel policy test "<コマンドまたはパス>"` | どのルールに当たるかを確認。 |

**管理**

| コマンド | |
|---|---|
| `zerostel status`／`zerostel doctor` | インストールと記録の状態。バグ報告にそのまま貼れる詳細チェック。 |
| `zerostel prune` | 30 日より古いセッション（`--older-than 7d`）と、それだけが使っていたスナップショットを削除。 |
| `zerostel projects` | 記録のあるすべてのプロジェクト（移動したものも含む）。どのコマンドでも `--project <id>` が使えます。 |
| `zerostel config` | 設定を表示。 |
| `zerostel completion <shell>` | bash、zsh、fish、PowerShell のタブ補完。例：`eval "$(zerostel completion bash)"`。 |

## ガードレール

ルールは `~/.zerostel/policy.json` に置きます。ファイルがなければルールもありません。`zerostel policy init` は入門用のルールを作成します。下記に加えて、管理者としての実行（`sudo`）、ソフトウェアのグローバルなインストール・削除（`npm -g`、`pip --user`、`brew`、`winget` など）、システムやユーザー設定の変更（`setx`、`reg`、`crontab` など）、システムフォルダへの書き込み、公開やデプロイ（`npm publish`、`terraform apply`、`vercel --prod` など）、テーブルの削除、そして Zerostel 自体を止める操作（`zerostel uninstall`、`zerostel prune`、エージェントのフック設定の変更）の前に確認します。ルールはコマンドの書き方で判定するので、足止めにはなっても壁にはなりません。それでもフックが外された場合はログに残ります。抜粋：

```json
{
  "rules": [
    { "action": "deny", "paths": ["~/.ssh/**", "~/.aws/**", "~/.gnupg/**", "~/.kube/**", "~/.config/gcloud/**", "~/.zerostel/**"],
      "reason": "credentials, and Zerostel's own records, are off limits" },
    { "action": "ask", "paths": ["**/.env", "**/.env.*"], "access": "write", "reason": "changes a .env file" },
    { "action": "ask", "commands": ["git push --force*", "git push -f*", "git reset --hard*", "git clean -*f*", "* --no-verify*"],
      "reason": "rewrites or throws away git history" }
  ]
}
```

`zerostel policy init` が作るファイルには `$schema` が入っているので、VS Code などのエディタで入力しながら補完とチェックが効きます（スキーマは `https://zerostel.com/schema/policy.json`、`config.json` 用もあります）。

- **`paths`** はツール呼び出しが指すファイルに一致します。シェルコマンド中に現れるパスも含みます。`~/` はホームフォルダ、それ以外の相対パスはプロジェクトのルートから。`**` はフォルダをまたぎ、`*` はまたぎません。`"access": "write"` でファイルを変更しうるツールだけに限定できます。
- **`commands`** はシェルコマンドの各部分（`&&`、`||`、`;`、`|` で分割）に一致します。`*` は何にでも一致します。
- **`tools`** はツール名に一致します（例：`"WebFetch"`、`"mcp__github__delete_*"`）。
- **`deny`** は実行前に止め、理由をエージェントに伝えます。**`ask`** は Claude Code ではあなたに確認を求めます。確認のために止まれないエージェントではブロックし、まずあなたに確認するようエージェントに伝えます。

コマンドは大文字小文字を区別せずに照合し、`&&`、`||`、`;`、`|`、`&`、`( )`、`$( )`、バッククォートで分割します。`$HOME/.ssh`、`%USERPROFILE%\.ssh`、Git Bash の `/c/Users/...` といった書き方も正しく解釈します。

ブロックや確認になった呼び出しは、タイムライン・Web 表示・レポートに表示されます。`policy.json` が壊れている場合は推測せず、`zerostel status` と `doctor` が知らせます。Zerostel 自体の問題でツールがブロックされることはありません。ガードレールはミスに対するシートベルトであってサンドボックスではありません。ファイル名を書かずにファイルへ届くコマンドもあります。

そのほかの既製ルール（秘密情報、アップロード、マイグレーション、メインブランチ、MCP ツール、依存パッケージ、CI 用の厳しい設定）はテスト付きで [docs/guardrails.md](docs/guardrails.md) にあります。

## CI で使う

GitHub Actions で無人実行されるエージェントにも、同じ記録・ガードレール・レポートが付きます。タイムラインはジョブサマリーに書かれ、レポートは実行結果に添付されます：

```yaml
- uses: zerostel/zerostel@v0
  with:
    agent: claude-code
    policy: .github/zerostel-policy.json
    run: claude -p "make npm test pass" --permission-mode acceptEdits
```

詳しくは [docs/ci.md](docs/ci.md)。

## エージェントから使う（MCP）

`zerostel mcp` は [Model Context Protocol](https://modelcontextprotocol.io) サーバーです。エージェント自身が、危険な操作の前にチェックポイントを保存し、タイムラインを読み、コマンドをあなたのルールで確認し、頼まれたら巻き戻せます（「ステップ 12 に戻して」「ゼロ地点に戻して」）。巻き戻しは適用を明示されるまでプレビューのみで、エージェントを起動したプロジェクトにしか作用しません。

`zerostel` をグローバルにインストール（`npm install -g zerostel`）したうえで、Claude Code に追加します：

```bash
claude mcp add zerostel -- zerostel mcp
```

Windows では `claude mcp add zerostel -- cmd /c zerostel mcp` を使います。Codex は `~/.codex/config.toml` から読み込みます：

```toml
[mcp_servers.zerostel]
command = "zerostel"
args = ["mcp"]
```

ほかのエージェントでも、MCP 設定に同じコマンドと引数を指定してください。

## 仕組み

```
 agent ──hook──▶ zerostel ──▶ policy.json      ツールの実行前にブロック・確認
 （各ツール呼び出し  │
  の前後）          └──────▶ ~/.zerostel/projects/<名前>-<hash>/
                              ├─ snapshots.git      シャドウリポジトリ、作業ツリー = プロジェクト
                              └─ sessions/*.jsonl   プロンプト、コマンド、ファイル、トークン、時間（ハッシュチェーン）
```

- **フック。** エージェントは各ツール呼び出しの前後と、各ターンの開始・終了時に Zerostel を呼び出します。読み取り専用のツールは記録のみ、ファイルを変更しうるツールは前後でスナップショットを取ります。
- **シャドウ git リポジトリ。** スナップショットは、作業ツリーがプロジェクトそのものである別リポジトリに保存されます。`.git`、ブランチ、インデックス、stash には一切触れず、プロジェクトが git リポジトリである必要もありません。ファイルはバイト単位でそのまま保存され、同じ内容は一度だけ保存されます。
- **スナップショットの対象。** `.gitignore` で除外されていないものすべて（`node_modules` などの依存フォルダを除く）。`.env` のような無視された小さなファイルもバックアップします。エージェントがそれを消したときこそ必要になるからです。`watch` に挙げたプロジェクト外のファイルは、専用のリポジトリに保存します。
- **安全な巻き戻し。** 復元の前に現在の状態をスナップショットするので、どの巻き戻しも取り消せます。そのスナップショットにコピーがあるものしか削除せず、シンボリックリンクやジャンクションをたどってプロジェクトの外に出ることもなく、復元後に結果を検証します。
- **検証できるログ。** 各イベント行には、前の行と自身に対する HMAC が付き、鍵は `~/.zerostel/audit.key` です。
- **邪魔をしない。** ルールが発動しない限りフックは何も出力せず、常に終了コード 0 で終わり、エラーは自分のログに書きます。Zerostel に問題があってもエージェントは動き続けます。

詳しくは [docs/architecture.md](docs/architecture.md)。

## 設定

`~/.zerostel/config.json`（すべて省略可）：

```json
{
  "maxFileMB": 25,
  "snapshotTimeoutSec": 20,
  "retentionDays": 30,
  "exclude": ["data/**", "*.sqlite"],
  "watch": ["~/.zshrc", "~/.bashrc", "~/.gitconfig"]
}
```

- **`maxFileMB`** — このサイズを超える新規ファイルはスナップショットされません。タイムラインに表示されます。
- **`snapshotTimeoutSec`** — 1 回のスナップショットがこれより長くかかると、そのプロジェクトでは 1 時間スナップショットを止め、タイムラインの記録は続けます。
- **`exclude`** — スナップショットしない git pathspec のグロブ。
- **`watch`** — ホームフォルダ内で、すべてのプロジェクトと一緒にスナップショット・巻き戻しするファイル（各 1 MB まで）。変更があると独立したステップとして表示されます。

## プライバシーとセキュリティ

すべてのデータは手元のマシンに残り、アップロードはしません。`~/.zerostel` はあなただけが読めます。

タイムラインにはプロンプト、コマンド、コマンド出力の末尾が保存されます。API キー、トークン、パスワードはできる範囲でマスクしますが、特殊な形式の秘密情報まで確実に隠せるわけではありません。ファイルの内容はスナップショットリポジトリにだけ保存されます。レポートには `.env` のようなファイルを含めず、`--share` ではプロンプト・コマンド・出力・差分を一切含めません。ファイルパスと時間は残ります。

Zerostel はプロジェクトを信頼しません。ファイル名が git のオプションやパターンになることはなく、リンクによってスナップショットや巻き戻しがプロジェクトの外に出ることもなく、プロジェクトフォルダ内のプログラムが git やシェルの代わりに起動されることもなく、出力中の端末制御コードは除去されます。`zerostel ui` は 127.0.0.1 だけで待ち受け、表示されるリンクに含まれるランダムなトークンが必要です。Zerostel が何を守り、何を守らないかは [docs/security-model.md](docs/security-model.md)（英語）で説明しています。問題の報告は [SECURITY.md](SECURITY.md) をご覧ください。

## 名前の由来

**Zero** trust（ゼロトラスト）＋ **Stella**（星）。AI エージェントは夜空の星のように増え続けています。Zerostel は、それらが最後に戻ってくる一点です。検証できる記録と、ゼロ地点へ戻る道。

## よくある質問

**エージェントはどれくらい遅くなりますか？** `scripts/bench.mjs` を Windows 11（ノート PC の i9、プロセス起動が最も遅い環境）で実行した結果です：

| | 1,000 ファイル | 10,000 ファイル | 50,000 ファイル |
|---|---|---|---|
| 読むだけのツール呼び出し | 0.16 秒 | 0.16 秒 | 0.16 秒 |
| 編集するツール呼び出し（前後にスナップショット） | 1.0 秒 | 1.2 秒 | 1.9 秒 |
| プロジェクトの最初のスナップショット（バックグラウンド） | 3 秒 | 35 秒 | 5 分 |

最初のスナップショットは全ファイルを一度読みます。セッション開始時にバックグラウンドで始まり、エージェントは待ちません。終わる前のステップもスナップショットなしで記録されます。スナップショットの容量は、おおよそプロジェクトの圧縮後のサイズに変更分を足したものです。`npm run build && node scripts/bench.mjs` で手元のマシンでも測れます。

**git で十分では？** 適切なタイミングでコミットや stash をしていれば、git は優れた復旧手段です。しかしエージェントはコミットの合間に、しばしばシェルコマンド経由で変更を加えますし、ツール呼び出しのたびにコミットする人はいません。Zerostel はそれを自動で、独自のリポジトリで行うので、履歴を汚しません。長期的な履歴は git と通常のバックアップに任せてください。

**jj はどうですか？** Jujutsu は `jj` コマンドを実行するたびに作業コピーをスナップショットし、undo できる操作ログも持っています。エージェントが適切なタイミングで jj を実行するなら、多くのニーズをカバーできます。Zerostel はステップごとのタイムライン、ガードレール、レポートを加え、誰も何かを実行する必要がありません。

**エージェントに組み込まれるべき機能では？** チェックポイントや権限ルールを持つエージェントは多く、それで足りるならそれを使ってください。Zerostel は、すべてのエージェントで同じ記録、同じルール、同じ undo を使いたい人のためのものです。両者は競合しません。

**snap-back や Entire との違いは？** snap-back もシャドウ git でスナップショットと undo を提供します。Entire はエージェントのセッションをあなたのコミットに結び付けます。Zerostel はスナップショットをエージェントの各ステップに対応させ、タイムライン、ガードレール、検証できるログ、Web 表示、共有できるレポートを加えます。

**サンドボックスですか？** いいえ。ガードレールはルールに書いたツール呼び出しを止め、巻き戻しはファイルを戻します。信頼できないコードを扱うなら、エージェントをコンテナや別アカウントでも動かしてください。

**undo でエージェントのしたことはすべて元に戻る？** いいえ。取得済みのファイル、つまりプロジェクトと `watch` に挙げたファイルを戻すだけです。コマンドがグローバルにインストール・削除したパッケージ（npm、pip、Homebrew）は、元に戻すためのコマンドと一緒にステップとして表示されます。巻き戻し時に一覧にしますが、代わりに実行することはありません。Windows で `setx` などにより変更されたユーザー環境変数は元に戻します。ネットワークリクエスト、デプロイ、データベースへの書き込み、本来の `.git` への変更は戻りませんし、エージェントの会話も巻き戻りません。それはエージェント側で巻き戻すか、新しいセッションを始めてください。

**一方のエージェントだけを undo して、もう一方は作業を続けられる？** 安全ではありません。undo はプロジェクト全体（または `--only` で指定したパス）を戻すので、その間の他のエージェントやあなた自身の変更も戻ります。`--dry-run` でプレビューし、同時に動かすエージェントには別々の worktree を使ってください。

**ディスクはどのくらい使いますか？** 同じ内容は一度だけ圧縮して保存されます。`zerostel status` で合計を確認でき、`zerostel prune` で古いセッションを削除できます。

**トークン数は請求額ですか？** いいえ。形式が分かっているエージェントのトランスクリプトから読み取ったもので、分からない場合は not captured と表示されます。`zerostel run` ではトークンは見えません。正確な数字はプロバイダーのダッシュボードで確認してください。

## 制限

- 復元できるのは取得済みの状態だけです。削除の後に記録を始めても、そのファイルは戻せません。
- 1 つのシェルコマンドの途中の状態はありません。同じコマンド内で作成・削除されたファイルは見えません。`zerostel run` はファイルが落ち着いてからスナップショットを取るため、短時間しか存在しないファイルを取りこぼすことがあります。
- プロジェクトの外では、`watch` に挙げたホームフォルダ内のファイルだけがスナップショットされます。Windows のユーザー環境変数（`HKCU\Environment`）は、それを変更するコマンドの前後でだけ読み取り、巻き戻しで元に戻します。値はあなたのマシン上のセッションログに保存され、レポートには含めません。グローバルパッケージは、元に戻すコマンドと一緒に一覧にするだけです。巻き戻し先の時点で存在しなかった監視ファイルはそのまま残します。それ以外のプロジェクト外のものは対象外ですが、触れたコマンドはタイムラインに残ります。
- 次のものはスナップショットされず、存在する場合は `zerostel log` に表示されます：無視されたフォルダ（`node_modules`、`dist/`、`.gitignore` の対象）、入れ子の git リポジトリとサブモジュール、リンクされたフォルダ（シンボリックリンク、ジャンクション）、`maxFileMB` を超える新規ファイル。
- ホームディレクトリやドライブのルートで起動したエージェントは、タイムラインのみでスナップショットはありません。
- 大文字小文字を区別しないファイルシステム（Windows、macOS の既定）では、大文字小文字だけを変える名前変更（例：`readme.md` → `README.md`）は変更として扱われません。
- WSL では、Windows ドライブ上（`/mnt/c/...`）のプロジェクトはスナップショットが遅くなります。Linux 側のファイルシステムに置いてください。
- ハッシュチェーンは、`audit.key` を持たないものによるログの編集を見抜きます。あなた自身のアカウントを使う人は鍵を読んでログを丸ごと書き換えられます。`~/.zerostel/**` を deny ルールに入れて、エージェントが触れないようにしてください。
- ガードレールはツール呼び出しに書かれた内容に一致します。ファイル名を書かずにファイルへ届くスクリプトやコマンドはすり抜けます。
